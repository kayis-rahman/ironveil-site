# Ironveil site: art and fact sources

All product claims below are limited to the named current code, approved plans and audit reports. The Ironveil repository is read-only for this website task. The Privacy page was fact-checked against these sources on 2026-10-18 and still needs the captain's approval before publication.

## Hero and public art

- **Hero:** `assets/source/hero/snowy-island-campfire.webp` is an optimized WebP derivative of the read-only source `projects/ironveil/.lavish/trailer-screenplay-references/01-1a.png` (snowy island and campfire; original 1672×941 PNG). The derivative retains 1672×941 dimensions and is approximately 40 KB. The captain approved the screenplay plates as the canonical Ironveil visual reference and specifically directed use of `01-1a.png` as the full-bleed website hero on 2026-10-11. The source file was not modified. The site uses the WebP in an accessible `<picture>` with descriptive alt text; the CSS gradient is only a text-legibility overlay. No reference-site artwork, generated art, storyboard stills or motion-study media is used.
- **Favicon and gameplay captures:** the captain approved these for public-site use on 2026-10-11; approval may be withdrawn before merge. `assets/brand/favicon.png` is used only as the favicon. `assets/source/gameplay/deity-select.webp`, `island-phone.webp`, `island.webp`, `result-win.webp` and `winter-island.webp` are approved early-build capture sources, not final store screenshots. The Demo & media page owns current capture availability; fresh captures are expected after the game rename. Build-time AVIF/WebP variants are generated for gameplay sources when site pages reference them.
- Audit context: `data/ironveil-gap-and-art-audit-v2/report.md`, “Art, audio and UI inventory” (lines 58–76), distinguishes shipped game assets from prototype-only art and notes that polished store key art/screenshots are missing. The screenplay-plate approval above is the later, specific approval for the site hero.

## Offline game, local data and online-code boundary

- **Offline play and local saves:** `projects/ironveil/docs/plans/offline-mvp.md:3-6,21-26,70-78` defines the offline game against a bot, local save/resume and history, with online play/accounts excluded from that MVP. `projects/ironveil/client/Autoload/GameState.Flow.cs:23-24,134-140,147-163,440-450,475-498` writes match saves, history and match records under Godot's app-specific `user://` store. `projects/ironveil/client/Autoload/PlayerSettings.cs:8-20` stores settings there too. The local game does not provide cloud synchronization; the project compliance note warns that deleting the app removes device-local saves (`projects/ironveil/docs/release/store-listing-compliance.md:19-22`).
- **Lazy optional online path:** the code repository also contains a separate account/API path. `projects/ironveil/client/Autoload/OnlineClient.cs:12-16,40-50` says it does not connect until an online screen asks and offline play does not depend on it; `client/project.godot:18-23` does not autoload it. `projects/ironveil/client/Core/Online/OnlineSession.cs:31-33,63-105,150-164` shows the session stores player ID, email, access token and expiry while dropping the password after sign-in. `client/Autoload/OnlineClient.cs:185-212` stores that session in encrypted app-sandbox storage and derives the encryption key locally using `OS.GetUniqueId()`; it does not show that identifier being sent to a service.
- **Service and alpha limitations:** `data/ironveil-signing-guest-auth-telemetry-audit-v1/report.md:38-52` documents the code boundary: online sign-up/login sends email/password, server passwords are bcrypt-hashed, authenticated online match calls use bearer tokens, no client analytics/crash SDK or client event-upload code was found, and the platform identifier is used locally for online-session encryption with no evidence it is transmitted. The report says live Pi alpha state is unverified (`:12`). `data/ironveil-pi-alpha-deploy-plan-v1/report.md:14,29,54-56,68` is a deployment plan, not proof of a running service: it proposes PostgreSQL persistence for accounts/matches and a 24-hour production turn window, leaves alpha retention/reset as an open decision, and lists live server state as unverified. Therefore this site does not claim a live Pi service, server-side retention period, or verified server log/backup policy. Any online alpha must receive a separately verified privacy notice before being offered.
- **Ads, purchases and analytics:** the approved offline MVP excludes online/account scope and monetization is deferred (`projects/ironveil/docs/plans/offline-mvp.md:21-26`; `data/ironveil-gap-and-art-audit-v2/report.md:49-50,110`). The Ironveil release compliance report states no purchase code or SDK was found (`projects/ironveil/docs/release/store-listing-compliance.md:43-47`); the signing/telemetry audit found no client analytics/crash SDK or event-upload code (`data/ironveil-signing-guest-auth-telemetry-audit-v1/report.md:47-52`). Site copy describes only the current offline MVP; it does not imply future online releases will have the same data practices.
- **Website hosting and analytics:** source HTML/CSS/JS is static and self-hosted. The site has no ad trackers, contact forms, third-party fonts or media players. Its GA4 integration in `scripts/site.js` is optional and consent-gated: the script is not requested until analytics is accepted, and the browser choice is stored locally. Pages deployment is GitHub Pages (`.github/workflows/pages.yml`, `docs/deploy.md`). GitHub's own hosting/privacy practices are outside this codebase; the Privacy page links to GitHub's privacy statement.
- **Support and contacts:** support and privacy requests use `support@ironvei-game.online`; general enquiries use `info@ironvei-game.online`; press and social enquiries use `social@ironvei-game.online`. Non-sensitive bug reports and alpha-access requests can also use this site's public GitHub Issues page (`https://github.com/kayis-rahman/ironveil-site/issues`); issues are public, and the site tells users not to post sensitive personal data. Official social accounts are Instagram `https://www.instagram.com/apricotz.inc/`, X `https://x.com/apricotzinc` and TikTok `https://www.tiktok.com/@apricotzinc`. Apricotz is the developer brand.
- **Privacy page source:** the game and service sections reuse `docs/release/privacy-policy.md` from the Ironveil repository (`origin/main` `88538c429a12405564bb5aa4a76f4a5f7e771a08`) as source text, fact-checked against this evidence map on 2026-10-18. Website analytics disclosures are based on this site's implementation in `scripts/site.js`. Claims that cannot be verified from code or audit evidence - the exact shipped build, whether any online/Pi alpha service is live, server-side logs, backups or retention, and telemetry in a shipped binary - are visibly marked unverified on the page.

## Platforms, pricing and turn window

- **Platform targets, not availability claims:** `projects/ironveil/docs/plans/offline-mvp.md:21-24` sets iPhone/TestFlight first and Android later. The same plan and `:86-96` record iPhone/iPad device-family work and unfinished TestFlight/Android setup. `data/ironveil-gap-and-art-audit-v2/report.md:18,44,98,104` notes missing mobile workloads/SDK/signing prerequisites and incomplete device acceptance. Accordingly the Release page says iPhone/iPad are planned first and Android is later; it does not claim that any public build, supported OS matrix or device compatibility has been released.
- **Price:** no public store submission is planned for the offline MVP (`projects/ironveil/docs/plans/offline-mvp.md:61-63`; `data/ironveil-gap-and-art-audit-v2/report.md:49,77,110`). Monetization is deferred (`data/ironveil-gap-and-art-audit-v2/report.md:49-50,110`), and no price is published in the current release material. The site says “Price: Not announced”; it does not call the game free.
- **Turn timing:** `projects/ironveil/client/Core/Balance.cs:18-38` defines the Test profile as 120 seconds and the Release profile as 24 hours (`24 * 60 * 60`). `projects/ironveil/docs/plans/offline-mvp.md:17-20` and `data/ironveil-pi-alpha-deploy-plan-v1/report.md:14,29` agree that production/Release uses a 24-hour turn window. The How to Play page identifies 120 seconds as the development Test profile and 24 hours as Release timing; it does not confuse the two-minute gameplay captures with the release value.

## Gameplay claims

Paths below are relative to the read-only Ironveil repository. These sources support Home and How to Play copy; any future wording that exceeds them must be re-verified.

- **Offline match and rival temperaments:** `docs/plans/offline-mvp.md:3-6,21-26` describes the offline game against a bot and excludes online play from MVP; `client/Core/RivalBrain.cs:7-20` defines Balanced, Raider, Gatherer and Turtle.
- **Playable gods and powers:** `client/Core/Characters.cs:6-18,24-34,41-54` defines the playable gods, their costs and scout duration. `client/Core/Rules.cs:316-360,628-687` verifies once-per-turn powers, ability validation and decoy placement; `:645-665` verifies shelter damage and the private three-round scout.
- **Season order and survival:** `client/Core/Rules.cs:22,115-125,881-903` sets the 56-round limit, summer/autumn/winter/thaw schedule with three winters, and exposure endings. `client/Core/Balance.cs:40-54` defines seasonal cold, warmth and resource availability.
- **Veil and scouting:** `docs/design/game-design-decisions.md:50-61` records rival visibility rules and exceptions; `client/Core/Rules.cs:660-665,710-717,735-737` implements the private scout and inventory-revealing rune.
- **Rune powers:** `client/Core/MatchState.cs:50-68` lists the six rune types; `client/Core/Balance.cs:56-66` sets spawn cadence and a three-rune invocation cost; `client/Core/Rules.cs:238-254,700-747` verifies invocation and effects.
- **Victory paths:** Survival by striking a rival or exposure is implemented at `client/Core/Rules.cs:547-550,897-903`. Dominance's two-resource lead across three types, checked after gathering or stealing, is implemented at `client/Core/Balance.cs:105-109` and `client/Core/Rules.cs:552-555,824-826`. Ragnarok's two-grid-step range, two-rune/two-food cost and two consecutive turns are set at `client/Core/Balance.cs:111-121` and implemented at `client/Core/Rules.cs:82-95,256-272,591-621`.
- **Save/resume and history:** `client/Autoload/GameState.Flow.cs:147-163,193-260,440-498` implements local match start, save/resume and history entries; `docs/plans/offline-mvp.md:3-6,70-78` and `data/ironveil-main-debug-session-v1/report.md` provide corroborating product evidence.
